# 自動檢查與驗收

## 執行現有專案檢查

每次主動讀 package.json、lockfile、CI、測試設定，選取實際存在的檢查；不得用 `--if-present` 的零退出碼冒充測試成功。先看 script 是否會寫外部資料／部署，再執行。使用者只要求文件時，不為了讓檢查綠燈新增產品設定或測試框架。

1. 記錄 commit、作業系統、Node/npm 版本、env 是否設定（只記名稱／存在性）。無 Node pin 時不要把工作機版本宣稱為 Vercel 的版本。
2. 優先在可還原的獨立目錄安裝，執行 npm ci；lockfile 不一致要列失敗，不回寫原檔。隔離補裝僅為診斷，清楚標明差別。
3. 執行 package scripts 裡存在的 lint、typecheck（或實際 check script）、test、build。不存在就「未驗證：未設定」；不臨時用 npx 抓最新版 checker。測試可平行，會寫同一輸出或需相依的步驟依序。
4. lint 若進入 ESLint 初始化提示，退出並記未驗證，不選 Strict／Base 去改產品設定。build 內的「Linting and checking validity of types」訊息也不代表有獨立型別檢查。
5. 保留指令、退出碼、失敗摘要、測試前提。只在變更、失敗修復或未解疑慮時重跑；不要反覆跑相同成功檢查。

基準 package scripts：dev=`next dev`、build=`next build`、start=`next start`、lint=`next lint`。無 typecheck/test scripts、ESLint config、測試檔與 CI。package-lock 缺 qrcode 及其相依，2026-10-28 npm ci 已重現 EUSAGE；這是需修的初始化缺口，不由本次文件 PR 修復。

## 分層驗證

| 層次 | 可證明 | 不可推論 |
| --- | --- | --- |
| 靜態程式／SQL 審查 | 實作路徑、可能缺口 | 真實 DB 政策或功能已通過 |
| lint／build | 指定環境的靜態檢查／編譯 | 身分授權、報名正確性、真機相容 |
| mock／純函式／瀏覽器 fixture | 指定受控情境的邏輯／畫面 | LINE 登入、Supabase RLS、正式資料一致 |
| 隔離 DB integration | 真實寫入、授權、交易 | 正式環境設定一致 |
| LINE iOS／Android 真機 | 指定裝置版本與流程 | 未測平台或版本 |

測試資料僅在隔離環境使用並標識為測試，不放正式畫面或 Skill 當真實名單。不能為了測試而讀／改正式客戶資料、實際群組或推播。

## 功能驗收表

每列記錄：通過／失敗／未驗證、commit、環境、步驟、期望、實際、證據。沒有執行就填未驗證。

| 項目 | 操作與期望 |
| --- | --- |
| 建立與連結 | 主辦人建立 normal/queue；欄位與模式正確，短連結開正確 task |
| 報名 | 單人、分類單／多選、必填、份數／人數、代報；DB 與成功回應一致 |
| 修改 | 正確本人可改名，空白／超限拒絕；改名 created_at 與順位不變；改數量重驗容量 |
| 取消 | 本人取消成功、他人被拒；名單／總數／順位同步；再加入到尾端 |
| 主辦人 | 本人的任務可讀／處理／匯出；錯誤 LINE 帳號、未登入不可讀他人名單或寫入 |
| 容量與期限 | 未開始／已截止／最後名額；同時搶額不超額，讀 DB 失敗不當 0 放行 |
| 候位一致性 | A/B/C 加入、完成、取消、重排；比對主辦人、每個參加者、同一後端快照 |
| 防重複 | 雙擊、重整、重開、網路重試、同身分平行 POST；有效候位至多一列 |
| 排序及大量資料 | 同 timestamp 用 id 固定；超過預設列數上限後總數／順位仍正確 |
| Loading／錯誤 | 延遲首載時無假 0；初載失敗可重試；後續 500 保留有效資料並顯示未同步 |
| 回應競爭 | 慢舊 GET/POST 狀態回應晚到，不蓋較新資料；切 task／卸載不更新舊畫面 |
| 等待時間 | 0、1、59、60 分鐘及超過 24 小時，持續以分鐘／小時顯示，返回後校時 |
| 小人唯一與位置 | 等待頁只有一個，位於文字上方；取消／完成／返回後不重複、不擋按鈕 |
| 隨機動畫 | 控制隨機源驗八種動作；相同順位可選多種，變順位不固定動作；泡泡適度 |
| cleanup | StrictMode mount/unmount、前後景、重開；無殘留 timer、observer、listener 或多重輪詢 |
| 手機版面 | 320/375/390/430 px、桌面、長姓名、鍵盤、橫向、safe area，無橫向溢出或截斷 |
| LINE 真機 | iOS／Android 分列，登入、返回、重開、分享成功／取消、外開下載與權限 |
| 個資隔離 | 直接 anon DB 查詢、錯本人 token、錯 LINE token、匯出，都拿不到他人明細／token |
| 內部標記 | task note/categories marker 不出現在前台、分享圖卡、匯出及編輯的可見文字 |

現版可預期失敗的案例也要保留，不能刪掉以取得全綠。修復才補對應回歸；避免只檢字串、class 名或鏡像實作的測試。

## Skill 本身驗證

優先執行當前可用的 skill-creator/scripts/quick_validate.py，另檢相對連結、YAML、未完成 placeholder、檔案清單及敏感資料。官方 validator 是結構檢查，不會執行業務驗收。

以三個實際提示走讀：新建活動報名（走 normal、容量與身份）、修候位假零（同源資料與狀態）、只建立文件（不得改產品／DB／部署）。另檢「做一般 LINE bot」不應誤觸發。若沒有獨立 agent 評估，明寫人工／本次 agent 走讀，不能稱獨立行為測試通過。
