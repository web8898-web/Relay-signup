# 標準製作流程

## A. 建立專案

1. 沿用已有需求，補問會影響架構的資料：主辦人／參加者、接龍或候位、名額按人或份數、分類與代報、開始／截止時間與時區、個資可見範圍、是否跨裝置、通知需求、部署目的地。不能把所有候位需求都推定為完整叫號。
2. 決定模式：一般接龍及活動報名使用 normal；現場逐一處理使用 queue。預約時段、多場次、候補名單或 called/serving 等需要明確擴充模型。
3. 先盤點新目標 repo 的真實結構與 scripts。既有專案保留 Next App Router／React／Tailwind 的慣例；新建可沿用 app/components/lib/sql 分層。建立 codex/ 分支，保護未提交變更。
4. 按 [database.md](database.md) 設定隔離資料庫和環境變數。先對帳 schema、batch_id、checked_in、task_mode；需要推播才補 notification_log 設計。不可直接把來源公開 RLS 當安全預設。
5. 建立前台報名／本人候位頁及主辦人任務／名單頁。讀取、寫入、匯出皆設伺服器授權，參加者只拿自己的明細與匿名統計。
6. 在開發前寫下 API 輸入輸出、資料狀態、權限和驗收矩陣。按 [testing.md](testing.md) 自動跑現有指令；依 [deployment.md](deployment.md) 準備 PR 與預覽。

產出：模式與規則摘要、路由／資料流、欄位與授權表、實作範圍、驗收案例。已知內容直接做，不為例行技術選擇重問使用者。

## B. 報名流程

| 步驟 | 實作與驗收重點 |
| --- | --- |
| 建立活動 | 主辦人 LINE 登入，server verify token + channel，再寫 creator_id |
| 名稱、時間、說明 | title/start/end 必填；現有只有日期，若需時分明列擴充，不把日期假裝時段 |
| 名額及規則 | 確認容量語義、分類單多選與必填、代報；新增和修改使用同一後端驗證 |
| 報名連結 | 產生唯一 short_code；短連結保留 mode/locale 等 query；不包含 owner token |
| 使用者報名 | 參加者身分憑證、輸入驗證、伺服器期限檢查、原子容量與冪等性；成功才顯示成功 |
| 狀態 | loading/error/empty/success 分離；未讀到值不能當 0；只顯示授權資料 |
| 修改／取消 | 伺服器確認本人；改名不變 created_at；數量變更重驗容量；取消完成後重取統計 |
| 主辦人管理 | 伺服器驗任務所有權；名單、點名、匯出各自授權。需要主辦人代改／代刪時另加明確權限 |

現況細節：人數單位「人／位／名／口」以本人 1 + 額外人數計算；商品份數不能混為人數。一般多名報名是多列，batch_id 表同批；候位禁代報。categories 與 note 的內部 marker 必須用 lib/utils 的可見內容函式過濾，分享、編輯與匯出也要驗證。

## C. 現場候位流程

1. 主辦人建立 queue 任務；確認開始／結束、同時等待上限、完成及重排規則。
2. 使用者輸入本人姓名；後端確認該身分在此 task 沒有有效候位，原子地新增。
3. 以資料庫時間記錄 created_at，取得不可混淆的資料 id；姓名不是身分鍵。
4. 後端計算等待總數，使用一致的任務篩選、waiting 定義及排序。
5. 從同一快照計算本人一基順位。
6. 從同一快照回傳前方等待數；不能用 DOM、頁面索引或前端假資料補算。
7. 使用單一更新控制器自動同步、阻止舊回應倒寫；背景返回時重新同步。
8. 本人可改名或取消；改名保留位置，取消離隊，再加入排到尾端並重設等待起點。
9. 主辦人依已確認規則處理候位。現有只有手動 checked_in，若需「叫下一位」必須設計交易／狀態與重複點擊防護。
10. 更新 waiting/completed 與本人狀態，讓主辦人和參加者使用同一後端口徑；成功回應後更新全部受影響畫面。

狀態與公式、併發測試見 [queue-system.md](queue-system.md)。畫面與動畫見 [ui-design.md](ui-design.md)。

## D. LINE 與回復

按 [line-integration.md](line-integration.md) 處理入口、LIFF、分享、WebView、返回／重開。不要把自動群組通知、跨裝置參加者登入或外開瀏覽器身分延續當成既有能力。

維護既有系統時先重現單一問題、讀實際呼叫路徑、限定變更範圍，再新增有意義的回歸。重構 DOM 補丁須同時移除相對應掛載，驗證不產生雙元件；文件任務只描述方案。
